# Asynchronous JavaScript

## Async Wait

**In JavaScript, the `async` keyword is used to define a function that always returns a Promise and allows the use of `await` within its body to pause execution until a Promise settles.**

## What `async` Does

- Placing `async` before a function declaration ensures that the function returns a Promise, even if it appears to return a plain value
- Example:
    
    `javascriptasync function myFn() {
      return "Hello";
    }
    *// Equivalent to:*
    function myFn() {
      return Promise.resolve("Hello");
    }`
    
- The actual return value is always wrapped in a resolved Promise, unless an error is thrown, in which case the Promise is rejected

## Using `await` Inside `async` Functions

- The `await` keyword can only be used inside an async function
- `await` pauses the function execution until the awaited Promise resolves, then resumes execution and returns the resolved value.
- Example:
    
    `javascriptasync function fetchData() {
      const response = await fetch("https://jsonplaceholder.typicode.com/posts/1");
      const data = await response.json();
      console.log(data);
    }
    fetchData();`
    
- This way, asynchronous code reads more like synchronous code, making it easier to understand and maintain.

## Key Points

- Async functions simplify working with Promises by making asynchronous logic appear synchronous
- They always return a Promise, which can be used with `.then` or caught with `.catch` (or via `try..catch` inside the function).
- Allows for improved error handling and linear, readable asynchronous code flow.

## Example Patterns

- Sequential, parallel, and concurrent execution using `async/await` enables various asynchronous control flows:
    - Sequential: Wait for each operation before starting the next.
    - Parallel: Launch multiple operations, then wait for all using `Promise.all` and `await`.

Async functions and the `await` keyword are fundamental for modern JavaScript development, especially when handling I/O, APIs, and other asynchronous tasks.

**Async functions in JavaScript differ from regular functions mainly in their return value and their ability to pause execution to wait for asynchronous operations using `await`**

## Key Differences

## Return Value

- **Regular functions** return values directly (e.g., strings, numbers, objects).
- **Async functions** always return a Promise, even if they seem to return a direct value.
    
    `javascriptfunction regularFn() { return 1; }
    async function asyncFn() { return 1; }
    
    console.log(regularFn()); *// 1*
    console.log(asyncFn());   *// Promise { <fulfilled>: 1 }*`
    

## Execution Behavior

- **Regular functions** execute synchronously: code runs line by line, blocking until each line completes.
- **Async functions** allow pausing execution inside them using `await`, making asynchronous code look synchronous without blocking the rest of the program. The rest of the code after an `await` resumes only after the awaited Promise settles.

## Use of `await`

- Only **async functions** support the use of the `await` keyword.
- `await` pauses execution inside the function until the awaited Promise resolves, making it easier to work with asynchronous APIs.

## Error Handling

- Inside **async functions**, `try...catch` blocks can be used to handle errors from asynchronous code just like synchronous exceptions.
- **Regular functions** require Promise `.catch()` chaining or error callbacks for handling asynchronous errors.

## Summary Table

| Feature | Regular Function | Async Function |
| --- | --- | --- |
| Return value | Direct (any type) | Promise wrapping return |
| Synchronous code | Yes | Top-level: Yes; can pause with `await` |
| Can use `await` | No | Yes |
| Error handling | try...catch (sync), `.catch()` (async) | try...catch (covers awaited Promises) |
| Example use case | Pure calculation | APIs, I/O, timers, etc. |

Async functions are thus essential for managing asynchronous programming in modern JavaScript, providing more readable and maintainable code compared to using Promises alone

## Promise

A **Promise** in JavaScript is an object that represents the eventual completion (or failure) of an asynchronous operation and its resulting value. It acts like a placeholder for a value that may not be available immediately but will be resolved at some point in the future. The Promise has three states:

- **Pending**: Initial state, neither fulfilled nor rejected.
- **Fulfilled**: The asynchronous operation completed successfully.
- **Rejected**: The operation failed with an error.

When a Promise is fulfilled or rejected, it triggers callback functions that handle the result or error through methods like `.then()`, `.catch()`, and `.finally()`. This allows asynchronous code to be written in a cleaner, more manageable way compared to traditional callbacks.

Promises are created using the `Promise` constructor which takes an executor function with two parameters: `resolve` (called on success) and `reject` (called on failure). For example:

`javascriptlet myPromise = new Promise((resolve, reject) => {
  *// asynchronous operation*
  if (operationSuccessful) {
    resolve("Operation succeeded");
  } else {
    reject("Operation failed");
  }
});

myPromise.then((value) => {
  console.log(value);  *// handle success*
}).catch((error) => {
  console.error(error); *// handle failure*
});`

Promises provide several static methods for advanced use cases, such as `Promise.all()` to wait for multiple promises to fulfill, or `Promise.race()` to settle as soon as one promise resolves or rejects.

In summary, Promises allow handling asynchronous operations in a structured way, avoiding callback hell and enabling chaining of asynchronous tasks efficiently
